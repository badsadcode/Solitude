# Stations from NoorLevel

Solitude's deep-sea station interiors are generated by **NoorLevel**
([badsadcode/BadLevel](https://github.com/badsadcode/BadLevel), `NoorLevel/`) and consumed as
**files** (studio rule: projects connect through files, never through each other's code).

## Pipeline

1. Build NoorLevel's CLI from its repo (`NoorLevel/src/NoorLevel.Cli`).
2. Run `tools/generate_stations.ps1 -Cli <path>\noorlevel-cli.exe`. It writes
   `assets/stations/<name>.glb` plus `<name>.recipe.json` (the exact command, preset and seed).
3. Godot imports the GLBs; `Scripts/Stations/StationInterior.cs` restyles, cuts and fills them at runtime.

The bank (2026-11-22): 64 stations in six families: research (facility), outpost (bunker),
habitat (compact), works (industrial), deeplab (facility, sci-fi), deck (techbase, one level).
The script never regenerates an existing GLB without `-Force` (saves remember loot positions),
validates each one, and writes `Scripts/Stations/StationBank.g.cs`. Each family stocks its loot
and crawlers differently (`StationInterior`). `-- --station-sweep` loads every station once.

Generator settings (see the script): originally the `facility` and `bunker` presets, `underground` (entered from
the top = the docking airlock; the exit = the station core), **no lifts / ladders / spiral stairs**
yet, ramps over stairs, no windows / skylights / open yards, one keycard door, a secret room.

What NoorLevel provides: the space, the mission structure (key before door, every room reachable,
validated), light positions. What Solitude adds: materials, lights and power state, doors that
open, loot, crew logs, the core's map fragment, creatures, navmesh.

## What Solitude reads from the GLB

| Data | Read as | Used for |
|---|---|---|
| Surfaces with material `nl_floor` / `nl_wall` / `nl_ceiling` | restyled (triplanar PS1 materials), trimesh collision | the station |
| `nl_door`, `nl_secret` surfaces | cut out, grouped by nearest door marker | openable bulkhead / hollow panel |
| `nl_sky`, `nl_trigger` surfaces | never rendered | — |
| marker `player_start` (+ `angle`) | airlock pose | where you board / leave |
| marker `light` | fixture + light (or dead tube / red emergency strip) and floor spot below it | lighting, loot and creature spawn spots |
| marker `exit` | the core terminal | map fragment, final log, power cell |
| marker `key` (+ `color`) | keycard pickup | opens the `door` with that `key` |
| marker `door`, `secret_door` | openable groups | |

The importer looks for Noor Interchange markers first (`extras.noor.marker`, e.g. `spawn.player`)
and falls back to what NoorLevel writes today (`extras.kind`).

## Proposal for NoorLevel (not applied — NoorLevel's call)

NoorLevel's exports and Noor Interchange v0.4 currently disagree:

- The plain `glb` export carries entities as `extras: {"kind": "light", ...}` at the top level of
  `extras`, not under `extras.noor`, and uses kinds outside the marker vocabulary
  (`player_start`, `exit`, `key`, `secret_door`, `lift`).
- The `noorengine` export writes a proper Interchange manifest and recipe, but its GLB has **no
  markers**: player start, lights and exit live only in the NoorEngine scene file.

Suggested change, so any engine can read NoorLevel levels from the GLB alone:

| NoorLevel today | Interchange marker |
|---|---|
| `player_start` | `spawn.player` (keep `angle` as node rotation, +Z forward) |
| `light` | `KHR_lights_punctual` point light (plus `light` marker if a hint is needed) |
| `exit` | `trigger` with `event: "exit"` (or propose a new `exit` marker in §3.4 first) |
| `key` | `pickup` with `class: "key"`, `props: {"color": "red"}` |
| `door` | `door` with `locked_by: "<key id>"` |
| `secret_door` | `door` with `tags: ["secret"]` |
| `lift`, ladders | `nav.link` with `kind: "lift"` / `"ladder"` |

Solitude's importer already accepts both forms, so either side can move first.
